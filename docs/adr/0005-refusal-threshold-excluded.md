# ADR-0005：拒答题默认不计入通过率

- 状态：已采纳
- 日期：2026-11-04

## 背景

检索类评测里有一类题叫"应拒答题"：语料里根本没有答案，正确行为是拒答。
报告里通常会给一个拒答阈值，以及在该阈值下的拒答正确率。

问题在于：**这个阈值是在同一批数据上挑出来的**——按 Youden J 取"分得最开"的那个点。
用它给自己的拒答打分，等于用答案调参再用同一批数据考试。更麻烦的是，每个臂的最优阈值
都不一样：跨臂比较时，差值里混进了"阈值调参"的成分，不再是纯检索质量的差。

## 决策

拒答题默认**不进通过率**，只记录一个观测指标 `unanswerable_top1_mean`（应拒答题的
top1 相似度均值，越低越好）。确实要纳入时必须显式 `--include-unanswerable`，
理由写进 `runs.config.note` 跟着数据走。

## 理由

- 避免循环论证：阈值由同批数据后验挑选，把它当成绩就失去意义；
- 让跨臂比较可比：比较的是同一口径下的检索质量，不掺阈值调参；
- 保留可观测性：`unanswerable_top1_mean` 能看出"这个臂是不是把什么都当有答案"，够用了；
- 不阻止想算的人：显式开关 + 落库理由，既不偷偷算，也不一刀切禁。

## 代价

- 通过率的分母变小（85 而不是 100），与"别人家的 100 题准确率"不能直接对齐；
- 完全忽略拒答行为会漏掉一类失败（该拒没拒）。缓解：`unanswerable_top1_mean` 仍在看板上，
  明显异常能看出来。

## 否决的方案

- **按报告自带的阈值算**：循环论证，见上；
- **用固定阈值统一判**：不同检索器、不同语料的分数尺度不同，固定阈值等于给不同臂设不同难度；
- **完全删掉拒答题**：丢掉了"该拒没拒"这个真实失败模式，也丢掉了语料覆盖不足的线索。
