# ADR-0004：指标一律从逐题明细重算

- 状态：已采纳
- 日期：2026-11-04

## 背景

送进来的评测报告通常自带一个"总结"字段：`accuracy: 0.91`、`full_coverage: 0.929`。
这些数字有三个问题：口径不明（分母是全部样本还是可答样本？跳过算不算失败？）、
无法核对（只有聚合值，看不到是哪些题错了）、以及**可能算错**。

在一份真实报告上就遇到过：作者改了口径但忘了重跑，总结字段比逐题明细算出来的值
高 2 个百分点。如果直接采信，后面所有比较都建立在一个不存在的差距上。

## 决策

平台只接受**带逐题明细**的报告，所有指标从明细重算；报告自报的聚合值不入库。
只有聚合结论、没有逐题明细的文件直接拒收（退出码 1）。

## 理由

- 口径统一：分母、跳过、异常值处理都由平台定义，跨项目可比；
- 可核对：任意一个数字都能追到具体哪几条题；
- 可配对：有了 `case_id` 才能做配对检验，聚合值做不了；
- 能发现上游算错：这次三份检索报告的自报值与重算值逐位一致——一致才有资格进入下一步比较，
  不一致就说明上游有问题，这本身就是有价值的信号。

## 代价

- 报告体积变大：逐题明细比聚合值大一到两个数量级。缓解：`detail` 字段入库时截断到 600 字符；
- 部分报告无法接入：只有聚合值的报告会被拒。这是刻意的——收进来等于替对方的统计口径背书；
- 重算逻辑要跟着口径演进维护：所以口径变更属于破坏性变更，必须升版本号并写进 CHANGELOG。

## 否决的方案

- **直接采信自报值，只在展示时核对**：核对不上时已经晚了，数据已经进了库、已经被比较过；
- **两者都存，冲突时报警**：存两份数字就得回答"以哪份为准"，最终还是会退化成采信自报值；
- **只要求提供原始日志，平台跑判分**：对上游侵入太强，且判分逻辑属于各自的评测框架，
  中台不该接管。
