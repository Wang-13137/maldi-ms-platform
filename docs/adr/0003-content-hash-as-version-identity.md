# ADR-0003：内容哈希作为数据版本身份

- 状态：已采纳
- 日期：2026-11-04

## 背景

"数据集 v2"这种命名是人为的，不可信：有人改了文件但忘了改版本号，有人把目录复制一份改名成
`v2_final`，还有人只换了列顺序。一旦版本的实际内容和它的名字对不上，后面所有"用 v2 复现"
的说法都失去意义——而评测中台存在的全部理由就是让结论可复现。

## 决策

数据版本的**身份**是内容哈希，不是名字。哈希的计算方式是：递归列出目录下所有文件，
按相对路径排序，对每个文件把 `相对路径 + 内容` 送进 sha256，最后得到整体摘要。

规则：**哈希相同即视为同一份数据；内容变一字节，哈希就变。**

## 理由

- 跨目录可复现：把数据集从 `G:/data` 拷到 `D:/backup`，哈希不变——身份与存储位置解耦；
- 排序保证确定性：不同操作系统的 `readdir` 顺序不同，不排序会得到不同哈希；
- 版本号退化为"人给这份数据起的别名"，不再承担身份职责。名字可以改，哈希不能。

## 代价

- 大目录首次登记要读一遍全部字节。当前数据量（几十 MB）是秒级；
- 目录里混入临时文件（`.DS_Store`、`__pycache__`）会改变哈希，所以实现了忽略列表；
- 只能证明"内容一致"，不能证明"来源可信"。来源可信要靠采集批次与审计日志，哈希不解决这个问题。

## 否决的方案

- **只记修改时间 + 文件大小**：改一个字节不改大小、或用 `touch` 改时间，都能伪造；
- **只记 git commit**：数据不在 git 里（真实数据永远不该进仓库），而且数据文件通常由
  采集设备产出，与代码仓库没有一一对应关系；
- **信任人工版本号**：这正是要解决的问题，不能拿它当答案。
